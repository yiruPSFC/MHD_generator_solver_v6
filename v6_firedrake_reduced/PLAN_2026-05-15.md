# Firedrake/Pyadjoint Reduced Functional Plan, 2026-05-15

## Core Decision

Build a separate `v6_firedrake_reduced` package to test whether a
forward-solve-eliminated reduced functional can reduce the continuation fragility
seen in the current CasADi/IPOPT full-space workflow.

The v0 forward solver is a Firedrake/PETSc nonlinear solve of the implicit
quasi-1D residual.  It is not RK4, Hermite-Simpson, or direct transcription.

## Model Contract

- State fields: `log(n_p)(x)`, `log(T_e)(x)`.
- Design variables: inlet/load variables plus low-dimensional direct `logA`
  spline controls.
- Fixed v0 parameters: magnetic field `B`, quasi-1D geometry, working fluid.
- Derived diagnostics: `T_p`, Mach, Velikhov margin, power density, outlet
  enthalpy extraction, outlet `T_e/T_p`, and energy budget.
- Failure rule: a failed forward solve is written to `failure_log.jsonl` and
  cannot be treated as a successful objective value.

## Implementation Phases

1. Establish the pure Python contract: design vectors, bounds, direct area
   spline geometry, JSON serialization, and profile objective diagnostics.
2. Add Firedrake forward solve with delayed imports so the package remains
   importable without Firedrake.
3. Add pyadjoint `ReducedFunctional` wrapper and a small multistart local
   optimizer.
4. Compare baseline evaluation artifacts against existing MAiNGO/CasADi
   profiles before trusting optimization results.

## Risks

- Firedrake/PETSc does not guarantee nonlinear forward convergence for arbitrary
  designs.  The first useful metric is forward-solve failure rate.
- The weak first-order residual formulation may need stabilization or a mixed
  DG/CG reformulation after the first smoke tests.
- Smooth penalties and aggregate diagnostics are deliberately used before adding
  many pointwise hard path constraints.
- pyadjoint gradients are meaningful only after the forward solve and objective
  are fully taped through Firedrake objects.
- Local macOS setup has two non-model hazards: PETSc cannot live under a path
  with spaces, and Conda compiler variables can poison CMake/Fortran builds.
  The current runtime uses `~/.cache/mhd_generator_solver_v6_firedrake/` plus a
  repo-local `.venv_firedrake` symlink and clean `env -i` commands.

## Acceptance Gate

- Baseline evaluation creates finite outlet metrics and a profile artifact.
- Failed starts are visible in `failure_log.jsonl`.
- At least 2-3 local starts run without hand-authored continuation schedules.
- One adjoint directional derivative agrees with finite difference within a
  loose tolerance on a tiny mesh.

## Checkpoint, 2026-05-19

Completed the first real reduced-functional wiring pass:

- Replaced the taped `Te/Tp` proxy with an enthalpy-extraction functional.
- Found and fixed a pyadjoint replay bug: scalar Firedrake `Constant` controls
  were not dependencies of the assembled forms, so the reduced functional was
  invariant under design perturbations.  Controls now use scalar `R`-space
  `Function`s.
- Reparameterized the solved state as inlet-relative `delta_log` fields so
  inlet DirichletBC values stay fixed at zero while inlet controls still enter
  the residual and objective.
- Replaced broad raw-variable L-BFGS-B smoke optimization with normalized
  projected-gradient/backtracking.  A trial is accepted only after a successful
  forward replay; failed trials remain artifact-visible.

Validated commands:

```bash
./.venv_jit/bin/python -m compileall v6_firedrake_reduced
./.venv_jit/bin/python -m unittest v6_firedrake_reduced.validation.test_pure_contract
env -i ... ./.venv_firedrake/bin/python -m unittest v6_firedrake_reduced.validation.test_firedrake_smoke
env -i ... ./.venv_firedrake/bin/python -m v6_firedrake_reduced.run_firedrake_reduced --case yamasaki2004 --mode evaluate --objective enthalpy_extraction --n-area-controls 3 --n-intervals 4 --out-dir v6_firedrake_reduced/outputs/enthalpy_tape_baseline_20260519
env -i ... ./.venv_firedrake/bin/python -m v6_firedrake_reduced.run_firedrake_reduced --case yamasaki2004 --mode optimize --objective enthalpy_extraction --n-area-controls 3 --n-intervals 4 --multistart 2 --out-dir v6_firedrake_reduced/outputs/enthalpy_tape_opt2_pg_20260519
```

Current result is still a tiny-mesh smoke result, not a physical claim:
baseline profile diagnostics report `3.125%` enthalpy extraction; the
`multistart=2` projected-gradient smoke reports a final profile diagnostic of
`9.801%` with zero failed trials.
